# SAR/GAMMA 数据处理部署与接口说明

本文说明当前项目如何从“知识助手”扩展到“可生成 Linux 处理配置的助手”。当前实现仍然不会执行 GAMMA；真实执行应放到安装了 GAMMA 的 Linux worker。

## 1. 推荐部署结构

```text
浏览器
  ↓
React 前端
  ↓
FastAPI 知识/RAG 后端
  ↓
FastAPI processing 配置接口
  ↓
Linux worker（后续阶段）
  ↓
gamma_dinsar / GAMMA / MATLAB / StaMPS
```

当前已经完成的是：

```text
React 前端
- 聊天问答
- 裁剪预览
- Linux 数据处理任务配置面板

FastAPI 后端
- /api/chat 知识问答
- /api/processing/defaults 读取默认参数
- /api/processing/config/preview 生成 YAML 预览
- /api/processing/tasks 保存任务草稿
```

还没有实现的是：

```text
- 真正执行 GAMMA
- SSH 连接 Linux
- Linux worker 队列
- 运行日志
- 暂停、恢复、取消任务
```

## 2. 当前本机测试端口

为了不影响原来的 RAG 后端，当前本机临时采用两个后端端口：

```text
前端：
http://127.0.0.1:5173/

RAG/LLM 后端：
http://127.0.0.1:8000/api/chat

Processing 配置后端：
http://127.0.0.1:8001/api/processing
```

对应 `.env.local`：

```text
VITE_ASSISTANT_PROVIDER=rag_api
VITE_RAG_API_URL=http://127.0.0.1:8000/api/chat
VITE_PROCESSING_API_BASE_URL=http://127.0.0.1:8001/api/processing
```

正式部署时可以把 RAG 和 processing 放在同一个后端端口，例如都放在 Linux 的 `8000`。

## 3. 新增后端接口

### 3.1 读取默认参数

```text
GET /api/processing/defaults
```

作用：

```text
- 返回代码默认参数
- 返回必须由用户填写的字段
- 返回建议显式展示的关键可选字段
- 返回最小 task.yaml 模板
```

这个接口不会读取用户数据目录，也不会执行外部程序。

### 3.2 生成 YAML 预览

```text
POST /api/processing/config/preview
```

请求格式：

```json
{
  "inputs": {
    "task_id": "demo_task",
    "task_root": "/data/gamma/demo_task",
    "raw_zip_dir": "/data/raw/sentinel1",
    "dem_file": "/data/dem/dem.tif",
    "master_date": "20240101",
    "bn_start1": "1",
    "bn_end1": "3",
    "env_scripts": [
      "/opt/gamma/env.sh",
      "/opt/stamps/env.sh"
    ],
    "matlab_func_dir": "/opt/matlab_funcs"
  }
}
```

返回内容包括：

```text
- status: ready 或 needs_input
- missing: 缺少的字段
- config_yaml: 可保存为 task.yaml 的配置文本
- effective_parameters: 应用默认值和自动推导后的最终参数
```

### 3.3 保存任务草稿

```text
POST /api/processing/tasks
```

作用：

```text
- 在应用自己的 runtime 目录下创建任务草稿
- 保存 task.yaml
- 保存 task.json 元数据
- 不执行 GAMMA
- 不写入用户指定的数据目录
```

默认保存位置：

```text
runtime/processing_tasks/<task_id>/
```

目录中会有：

```text
task.yaml
task.json
```

## 4. Linux 上正式部署时怎么改

如果要在 Linux 上进行真实数据处理，建议让 Linux 同时运行：

```text
- FastAPI 后端
- processing 接口
- 后续 Linux worker
- gamma_dinsar 代码
```

前端只需要改接口地址：

```text
VITE_RAG_API_URL=http://<LINUX_IP>:8000/api/chat
VITE_PROCESSING_API_BASE_URL=http://<LINUX_IP>:8000/api/processing
```

Linux 后端启动示例：

```bash
cd /path/to/zhushou
python -m uvicorn backend.main:app --host 0.0.0.0 --port 8000
```

如果需要保存任务草稿到指定目录：

```bash
export PROCESSING_TASKS_DIR=/data/sar_assistant/runtime/processing_tasks
```

注意：不要把 `PROCESSING_TASKS_DIR` 指向原始数据目录或最终结果目录。

## 5. 后续接入真实执行的边界

后续 Linux worker 应该只从已经确认的 `task.yaml` 读取参数，然后调用已有的 `gamma_dinsar`。

推荐状态流转：

```text
pending_review
  ↓ 用户补全配置
ready_for_linux_worker
  ↓ 用户确认开始执行
queued
  ↓ worker 接收
running
  ↓ 需要裁剪
waiting_for_crop
  ↓ 用户在网页框选裁剪范围
running
  ↓
succeeded / failed
```

当前代码只实现到：

```text
pending_review
ready_for_linux_worker
```

这样可以先把参数学习、配置生成和目录结构弄清楚，再进入真实执行阶段。
